## [0.26.1] - 2026-10-21

### Changed
- session: `stt` (the session token type) is now a protected access token payload claim, like `sub` or `exp`, and access tokens with an `stt` claim other than `0` are rejected. `CreateNewSession` drops an `stt` key from the access token payload it is given, and `MergeIntoAccessTokenPayload` drops it from the session's current payload, but an `stt` key in the update passed to `MergeIntoAccessTokenPayload` is still set, and makes the session's access tokens invalid unless its value is `0`. So if your app sets a custom access token claim named `stt`, rename it before upgrading. Existing sessions whose access token payload carries a custom `stt` claim are not revoked, but after the upgrade requests using them get a 401, and they can't be refreshed or signed out until they are repaired. Repair them with `session.MergeIntoAccessTokenPayload(sessionHandle, map[string]interface{}{})`, which removes the claim from the session, or revoke them.
- webauthn: account recovery now replaces the account's existing passkeys with the newly registered one and signs out its existing sessions if the account's email was not verified before the recovery. Accounts with a verified email keep their passkeys and sessions. The Go SDK doesn't mark WebAuthn emails as verified, so unless an account's email was verified another way, every account recovery resets the account's passkeys and sessions.
- thirdparty: the GitHub provider now validates the access token with GitHub (using `ValidateAccessToken`) on every sign in, which needs the client's `ClientSecret`. Add it to the GitHub provider config, or set a custom `ValidateAccessToken`.
- thirdparty: the Apple form_post callback now removes `.` and `..` segments (also percent-encoded ones, such as `%2e%2e`) from the path of `frontendRedirectURI` the way browsers do, and converts the host of an http(s) `frontendRedirectURI` to its IDNA (punycode) form if it isn't ASCII, then checks it, passes it to `IsValidFrontendRedirectURI` and redirects to it in that form (e.g. `https://app.example.com/a/../cb` becomes `https://app.example.com/cb`, and `https://bücher.example/cb` becomes `https://xn--bcher-kva.example/cb`). The default check compares hosts in their IDNA (punycode) form, so an `Origin` / `WebsiteDomain` with an internationalised domain matches redirects to it in either form. http(s) targets whose host is not a valid domain name after the conversion (e.g. it contains `/` or `@`, or has an empty label) are rejected. `IsValidFrontendRedirectURI` functions should parse the URL (e.g. with `url.Parse`) and compare its scheme, host, port and path instead of comparing strings.
- thirdparty: when the Google Workspaces provider is configured with a specific `hd` (in `AdditionalConfig`), sign ins without a verified id_token (e.g. with only an access token) now require the `hd` claim of the user info response to match it, as sign ins with an id_token already did. An empty `hd` has to match like any other value; leave `hd` unset or set it to `*` to allow any Google account.
- dashboard: the dashboard's tenants list API (`/dashboard/api/tenants/list` under your API base path) now returns only each tenant's id and whether its email password, passwordless and third party login methods are enabled, without the tenant's third party provider configs. If your code reads the providers from this API, use `multitenancy.GetTenant` on your backend instead.
- multitenancy: an overridden `GetTenantId` now also runs for requests without a `rid` header, including requests to the JWKS and OpenID discovery endpoints, so it runs for every request the SDK's middleware handles (with the tenant id from the path, or `public`). Make sure your override handles these requests too, e.g. that it doesn't reject requests to the JWKS endpoint.
- passwordless: consuming a code now marks the user's email as verified only if the code was sent to that email. Signing in with a code sent to a phone number no longer verifies the email of a user who also has one; verify it with the EmailVerification recipe instead. This adds one core call to the consume code API.
- openid: `JwtValiditySeconds` in the `openid.Init` config is now passed to the JWT recipe, so JWTs created without an explicit validity (e.g. with `openid.CreateJWT`) now expire after that many seconds instead of using the default of 100 years. If you set it, check that the value is what you want.
- session: `FetchAndSetClaim` and `FetchAndSetClaimWithContext` on a `SessionContainer` now fetch the claim value for the session's tenant instead of `public`, like `session.FetchAndSetClaim` with a session handle already did. For example, `UserRoleClaim` and `PermissionClaim` now use the user's roles in the session's tenant, `AllowedDomainsClaim` gets the allowed domains of the session's tenant, and custom claims get the session's tenant id as the `tenantId` argument of their fetch function.
- session: `ValidateClaimsForSessionHandle` now fetches claim values for the session's tenant instead of `public` (e.g. `UserRoleClaim` and `PermissionClaim` now use the user's roles in the session's tenant). The access token payload it passes to `ValidateClaims` now includes the session's tenant id (`tId`), and protected claims (such as `tId`, `sub` or `exp`) in the `AccessTokenPayloadUpdate` that `ValidateClaims` returns are no longer merged into the session's access token payload.
- thirdparty: the Google (including Google Workspaces), Facebook, GitLab and Discord providers now check access tokens sent to the sign in up API in `oAuthTokens` with the provider before using them, and fail the sign in if the token wasn't issued to one of the provider's configured clients. Sign ins with an authorisation code (`redirectURIInfo`) are not affected. Google: the token info API must return one of the configured client ids as `aud` or `azp`, so add every client that requests tokens for your app (e.g. web, Android and iOS) to the provider's `Clients`. Facebook: the check uses Facebook's debug token API, which needs the client's `ClientSecret`, so add it to the provider config. Setting `ValidateAccessToken` in the provider config replaces this check.
### Security
- Third-party sign-in now requires the `aud` claim of a provider's id_token to match the configured client ID, and rejects id_tokens when no client ID is configured.
- The user dashboard's `Admins` restriction now matches the sign-out and analytics exemptions against the request path only, so other write operations by non-admin dashboard users are always rejected.
- thirdparty: the Apple form_post callback now only redirects to the configured `Origin` / `WebsiteDomain` and answers invalid callback state with a 400. Apps whose `Origin` depends on the request, or that redirect to other targets (e.g. another origin, https universal/app links or custom-scheme mobile deep links such as `myapp://callback`), can allow them with the new `IsValidFrontendRedirectURI` thirdparty config option. `javascript:`, `data:` and similar schemes are always rejected.
